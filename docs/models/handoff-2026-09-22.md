# Deployed state, 2026-09-22 — and where it diverges from this repo

**The config in `configs/hermes/config.yaml` is not what is running.** A Windows
deployment (Hermes Agent v0.21.3, `%LOCALAPPDATA%\hermes`) has drifted from the
four-tier design this repo commits, on five axes. This file is the record of that
drift so the next session starts from fact rather than from the template.

Recorded from an operator handoff, not from inspection: nothing here was verified
against the machine, which is not reachable from CI or from a Linux session. Every
row below is "the handoff says", and the ones that matter are flagged for re-check.

## Three ways that config dies silently — now asserted in CI

The deployed shape hits all three, and none of them raise an error at runtime.
Hermes resolves a dead reference by falling back to the main model, so the symptom
is a bill and a latency change, not a stack trace.

1. **A reference names an excluded provider.** `excluded_providers` still carries
   `openrouter`, `anthropic`, `deepseek` and `ollama`. The reported MoA block names
   `openrouter` and `anthropic`; the reported parent is Anthropic. Exclusion matches
   case-insensitively against every key a provider surfaces under, so those
   references resolve to nothing. This is the same failure `or-fallback`'s rename
   exists to prevent, one layer up — the old check only compared exclusions against
   the `providers:` dict, never against what the rest of the file points at.
2. **`custom:X` after a rename.** `providers["nvidia-nim"]` is asserted by name.
   A deployed config using `provider: nvidia` leaves every `custom:nvidia-nim`
   reference dangling.
3. **Auxiliaries pointing at a provider that no longer exists.** All seven name
   `custom:hf-router`. Drop that provider and the slots revert to `auto`, which
   means the parent — Sonnet 5 generating session titles, on the parent's bucket.

`checks.yml` now resolves every provider reference in `model`, `delegation`,
`auxiliary.*` and `moa.*` against both the `providers:` dict and
`excluded_providers`. It fails on any of the three.

## Rotate the Render token

The handoff states the deployed `config.yaml` **previously held an inline Render
bearer token**. Render MCP is disabled there now (`mcp.render.com` failed DNS
repeatedly), but disabling a server does not un-expose a credential.

Rotate it in the Render dashboard. It persists in shell history and in at least the
four `config.yaml.bak-*` files the handoff lists. Deleting the line is not the fix;
rotation is. Re-enable Render only after the token is new and read from the
environment.

1. **hermes-council** — configured and enabled, but `python -m hermes_council.server`
   raises `ModuleNotFoundError: No module named 'mcp.server.fastmcp'`. The package
   imports; the MCP entrypoint does not. Reconcile the MCP SDK version in the Hermes
   venv, or disable the entry while debugging rather than leaving it crash-looping.
2. **Codex bridge handshake** — `codex mcp list` reported the

   never appeared, transfer stopped. Expect ~6.6 GB. Do not point Hermes at it until
   Ollama loads it *and* a tool-call test passes, not just a generation test.

## Two design notes for whoever reconciles this

**Six tiers undoes a deliberate four.** Commit `76eadb3` pinned the picker to four
tiers, and `discover_models: false` plus `excluded_providers` exist to keep it there.
The handoff's strategy lists six. If that is the target, the pin needs rewriting on
purpose — not eroding one provider at a time.

**MoA inverts this config's stated constraint.** The config header says the binding
constraint is "not money, it is requests." MoA spends at least two inference calls
per turn and puts a paid Sonnet 5 aggregator on every one. That is a defensible
trade for hard problems and a bad default. If MoA stays, it belongs behind an
explicit preset rather than on the default path.

**On the local floor.** Hermes 3 8B is a generation behind. Hermes-4-14B at IQ4_XS
is 8.11 GB against Nemotron Nano Q6_K's ~6.6 GB — the same laptop class — and it is
NousResearch's own post-train for ChatML, function calling and structured output,
which Hermes 3 predates. If the floor is being rebuilt anyway, the 14B at IQ4_XS is
the stronger tool-caller for roughly the same resident memory. See `local-floor.md`.
